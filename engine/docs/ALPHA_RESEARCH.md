# Alpha Research и проверка стратегии

## Цель

Research Layer не ищет красивую equity-кривую. Он пытается опровергнуть гипотезу о наличии альфы до того, как стратегия получит право отправлять сигналы в Execution Engine.

## Данные

Каждый dataset:

- содержит один символ и один интервал;
- состоит только из закрытых свечей;
- проходит проверку порядка, дубликатов, gaps и OHLC-инвариантов;
- хранится неизменяемо;
- имеет SHA-256 fingerprint;
- фиксирует source и временной диапазон;
- сохраняет missing OI/funding как missing;
- не позволяет использовать feature до `available_at_ms`.

Любая замена содержимого под тем же `dataset_id` отклоняется.

## No-look-ahead контракт

Стратегия получает только prefix истории до текущей закрытой свечи. `SignalDecision.feature_time_ms` не может быть позже времени закрытия свечи решения. Вход моделируется не раньше следующей свечи.

## Walk-forward

Каждый fold состоит из:

```text
TRAIN → PURGE → TEST → EMBARGO
```

Параметры выбираются только на TRAIN. Итоговые метрики формируются только из TEST-участков. OOS-окна не перекрываются и одинаковы для:

- SMC-стратегии;
- trend baseline;
- mean-reversion baseline;
- deterministic random baseline;
- stress scenarios.

## Baseline

Baseline confidence не сравнивается со шкалой confidence SMC, потому что эти шкалы не калиброваны друг к другу. Для baseline отключается только confidence threshold; комиссии, latency, sizing, stop/TP и все остальные условия остаются теми же.

Стратегия должна превзойти лучший baseline по expectancy с заданным запасом. Это уменьшает риск принять за альфу общий тренд рынка или удачную механику выходов.

## Симуляция исполнения

Симулятор учитывает:

- delayed entry;
- maker limit и ожидание fill;
- aggressive fallback;
- направленное adverse slippage;
- missed fills;
- maker/taker fees;
- funding;
- stop slippage;
- gap-through-stop execution;
- cost-aware position sizing;
- conservative same-bar SL/TP ambiguity;
- breakeven, trailing и time exit.

Плановый размер позиции рассчитывается по риску до initial stop с резервом на комиссии и настроенное stop slippage. Гэп способен превысить плановый риск — это не устраняется математически.

`risk_per_trade_pct` — верхняя граница, а не фактический риск. Если раньше
срабатывает `max_position_notional`, размер определяет notional cap, и
фактический риск на сделку оказывается меньше заявленного профилем. На
дефолтной конфигурации это происходит регулярно, поэтому отчёт содержит
предупреждение с фактической долей риска, а bootstrap компаундит именно её.

## Агрегированная equity-кривая

Каждое walk-forward окно симулируется от `initial_equity`. Абсолютные суммы
разных окон принадлежат разным режимам equity, поэтому их нельзя складывать в
одну кривую: полученная просадка описывала бы путь, которым не мог пройти ни
один счёт. Агрегат собирается иначе — каждая сделка воспроизводится по
фактически взятой доле риска от текущего equity, все денежные поля
масштабируются одним коэффициентом, `r_multiple` при этом не меняется, а
`max_position_notional` применяется заново на новом уровне equity. Поэтому
`max_drawdown_pct` и `return_pct` в Alpha Gate — это просадка и доходность
компаундящегося счёта, сравнимые с квантилями просадки из bootstrap.

Per-fold `test_metrics` остаются независимыми: каждый fold по-прежнему считается
от `initial_equity`, и критерий «доля положительных fold» использует expectancy в
R, который от уровня equity не зависит.

## Bootstrap

Используется block bootstrap последовательности R-multiples, чтобы частично сохранить кластеризацию результатов. Оцениваются:

- вероятность положительного expectancy;
- квантили expectancy;
- квантили максимальной просадки.

Bootstrap не делает нестационарный рынок стационарным и не заменяет live forward test.

## Stress suite

По умолчанию проверяются:

- удвоенные комиссии;
- удвоенное entry/stop slippage;
- 20% missed fills;
- дополнительная свеча latency;
- combined adverse scenario.

Стратегия не допускается, если проходит недостаточная доля стрессов.

## Alpha Gate

Стандартные пороги:

| Проверка | Порог |
|---|---:|
| OOS folds | ≥ 2 |
| Положительные folds | ≥ 60% |
| OOS trades | ≥ 80 |
| Expectancy | ≥ 0,05R |
| Profit factor | ≥ 1,15 |
| Max drawdown | ≤ 15% |
| Bootstrap P(E>0) | ≥ 90% |
| Stress pass ratio | ≥ 60% |
| Превосходство baseline | ≥ 0,02R |
| OOS return | > 0 |

PASS означает только «не отклонена текущим набором проверок».

## Защита от подгонки

- ограниченная parameter grid;
- параметры выбираются отдельно на каждом TRAIN fold;
- итог только на OOS;
- fingerprint кода и параметров;
- immutable reports;
- ручное продвижение;
- frozen shadow/testnet run;
- запрет незаметной смены symbol, interval или profile.

Нельзя многократно менять стратегию после каждого FAIL и считать последний PASS независимым доказательством. Все попытки и версии должны сохраняться в audit trail.

## Что исследование не моделирует полностью

- точную очередь maker-заявки;
- микросекундный intrabar path;
- реальный market impact;
- outage биржи;
- liquidation/ADL во всех режимах;
- изменение fee tier;
- будущую смену рыночного режима;
- ограничение capacity при масштабировании.

Поэтому обязательны SHADOW, TESTNET и минимальный live notional.
